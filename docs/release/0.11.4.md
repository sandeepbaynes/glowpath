# Glowpath 0.11.4

Horizontal countdowns now use the fold display's launch treatment. The rocket advances along a ticked flight rail, leaves a trail, and builds exhaust as launch approaches. The remaining-time readout stays anchored. Phone, tablet, desktop and compact horizontal layouts share this treatment; the vertical fold timer keeps its existing direction.

The countdown mechanics, pause behavior, haptics and failure transition are unchanged. App and system reduced-motion settings suppress travel animation while keeping time and thrust status visible.

Validation: **905 Flutter tests pass**, with clean static analysis. Phone, tablet and desktop renders were visually inspected at early and late countdown states; timer strips also cover expiration. The horizontal rail's easing settles between clock updates so normal gameplay and accessibility views remain stable. An Android release-build startup crash in WorkManager's generated Room database was corrected by retaining its public constructor in R8. The rebuilt APK launches on Android 16 phone, tablet and book-fold emulators and on Android 7.0 (API 24), the current Flutter minimum. Onboarding and gameplay were visually inspected on API 24; physical fold and broader older-device QA remain pending.

The [ad and analytics plan](AD_AND_ANALYTICS_PLAN.md) describes proposed placements and measurements. A local pacing rule and bounded on-device event journal are wired to game transitions. They cannot show ads or upload events. Production AdMob units exist for iOS and Android, but live ad integration, consent, hosted measurement and player-facing placement review remain separate release work.

Cloudflare tooling is installed locally in `tools/cloudflare`. A named `glowpath` profile has been authenticated and can list the intended account's Pages projects; it has no directory binding and does not replace the machine's global Wrangler default. No Glowpath Pages project or deployment exists yet. Live ads and purchases remain disabled in the web preview.
